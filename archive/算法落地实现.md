# 1. 算法整体理解

## 1.1 核心目标

该算法的工程目标不是做一个“统一打分器”，而是实现一个**任务自适应、长期记忆增强、可流式处理、多专家协作**的视频摘要系统。

它要解决的核心问题有 4 个：

1. **不同视频需要不同摘要策略**  
   旅行 vlog、体育比赛、教学视频、剧情视频的“重要片段”定义不同。

2. **长视频无法一次性细粒度全局建模**  
   需要“全局粗理解 + 局部顺序处理”的双时间尺度机制。

3. **摘要不仅保留高光，还要保留主线推进**  
   否则会得到零散高分片段，叙事不完整。

4. **流式处理必须利用历史信息抑制冗余**  
   当前窗口是否值得选，取决于它相对历史摘要记忆的边际贡献。

---

## 1.2 主要创新点提炼

### 创新点 1：动态摘要目标建模
先从全视频粗粒度语义中得到全局主题，再生成当前视频特定的摘要目标 `q`，而不是对所有视频使用统一标准。

### 创新点 2：双时间尺度处理
- **全局低频**：粗分段 + 全局故事理解
- **局部高频**：滑动窗口 + 顺序决策

### 创新点 3：多 Agent 专家协同
用多个专家分别评估：
- 主线推进
- 事件高光
- 新颖性
- 时序连续性
- 领域偏好

### 创新点 4：长期记忆增强的边际贡献估计
当前窗口不是独立评分，而是根据历史记忆判断：
- 是否重复
- 是否补充主线
- 是否对最终摘要不可替代

### 创新点 5：反事实评论家 CMCC
显式估计“如果删除该窗口，摘要信息会损失多少”。

### 创新点 6：Training-Free 决策架构
整个系统不依赖任务数据训练，而是基于：
- 预训练视觉/多模态模型提供表征；
- Planner + Expert Agent 的结构化规则协同；
- 长期记忆检索与启发式边际贡献评估；
- 可解释的路由、评分、融合和预算选择机制。

---

## 1.3 整体 Pipeline

完整 Pipeline 可落地为以下阶段：

1. **视频预处理**
   - 读取视频
   - 切镜头/粗分段
   - 构造滑动窗口
   - 采样帧

2. **全局理解**
   - 对粗分段生成 caption
   - 聚合为全局故事摘要
   - 生成主题分布与摘要目标

3. **局部感知**
   - 对每个窗口提取视觉特征
   - 生成局部 caption
   - 融合为多模态表示

4. **记忆读取**
   - 从历史摘要记忆中读取上下文、已覆盖主线、冗余信息

5. **规划与路由**
   - Planner Agent 根据当前窗口、全局目标、记忆状态生成专家权重

6. **专家评估**
   - 多个专家分别打分

7. **反事实校准**
   - 用 CMCC 估计窗口相对记忆的边际效用

8. **窗口分数生成**
   - 基础专家分数 + 反事实增益

9. **帧级映射与平滑**
   - 将窗口分数映射为帧级分数
   - 处理重叠窗口

10. **预算约束摘要选择**
   - 在预算 `B` 下选择片段生成摘要

11. **输出**
   - 帧级分数
   - 片段摘要
   - 决策日志

# 2. 系统架构设计

## 2.1 输入数据结构

建议先统一数据契约，避免后期模块耦合失控。

### `VideoMeta`
```python
from dataclasses import dataclass
from typing import Optional, List, Dict

@dataclass
class VideoMeta:
    video_id: str
    file_path: str
    fps: float
    total_frames: int
    duration_sec: float
    title: Optional[str] = None
    asr_segments: Optional[List[Dict]] = None
    category: Optional[str] = None
```

### `Segment`
粗分段或镜头段。
```python
@dataclass
class Segment:
    seg_id: str
    start_frame: int
    end_frame: int
    start_sec: float
    end_sec: float
```

### `Window`
滑动窗口单元。
```python
@dataclass
class Window:
    win_id: str
    start_frame: int
    end_frame: int
    sampled_frame_indices: list[int]
```

### `WindowFeature`
局部多模态表示。
```python
@dataclass
class WindowFeature:
    win_id: str
    visual_description: str
    local_caption: str
    semantic_summary: str
    evidence_notes: list[str]
```

### `MemoryState`
长期记忆快照。
```python
@dataclass
class MemoryState:
    story_slots: list[str]
    selected_slots: list[str]
    redundancy_bank: list[str]
    temporal_context: list[str]
```

### `PlannerOutput`
```python
@dataclass
class PlannerOutput:
    route_plan_text: str
    focus_points: list[str]
    routing_rationale: str
```

### `WindowScore`
```python
@dataclass
class WindowScore:
    win_id: str
    expert_opinions: dict[str, str]
    base_decision: str
    cf_comment: str
    final_importance: str
```

## 2.2 模块设计

### Module 1：Data Ingestion / Video Loader
- **功能**：读取视频、元信息、ASR、标题、标签
- **输入**：视频路径、元数据文件
- **输出**：`VideoMeta`
- **内部算法逻辑**：
  - OpenCV / decord 获取 fps、frame 数
  - 加载可选辅助模态
  - 统一为内部元数据对象

### Module 2：Video Segmenter
- **功能**：粗分段 + 滑动窗口构造
- **输入**：`VideoMeta`
- **输出**：`List[Segment]`, `List[Window]`
- **内部算法逻辑**：
  - MVP：定长粗分段 + 固定窗口滑动
  - 升级版：TransNetV2/pySceneDetect 做镜头切分
  - 窗口参数：`win_len`, `overlap`, `sample_rate`

### Module 3：Global Understanding Module
- **功能**：构建全局故事与摘要目标
- **输入**：粗分段、分段采样帧、可选标题/ASR
- **输出**：
  - `global_captions`
  - `global_story`
  - `theme_dist`
  - `summary_goal`
- **内部算法逻辑**：
  1. 对每个粗分段生成 caption
  2. 聚合 caption 得到全局摘要
  3. 生成主题分布
    4. 将全局摘要整理为下游 Agent 可直接消费的目标文本 `q`

**实现约束：**
- 使用外部或本地 **冻结的** Video LLM / MLLM / 文本 LLM；
- 禁止对 captioner、encoder、aggregator 做任何微调；
- 若无大模型，可退化为规则摘要器 + 预训练文本编码器。

> 工程建议：  
> 初期可不直接依赖大型 Video LLM。可先用：
> - 图像编码器 + 简单模板 caption
> - 或 BLIP / InstructBLIP 做近似

### Module 4：Local Perception Module
- **功能**：窗口级多模态表示提取
- **输入**：`Window`
- **输出**：`WindowFeature`
- **内部算法逻辑**：
    - 均匀采样帧
    - 调用视觉描述器生成窗口视觉文本描述
    - 调用 caption 模块生成局部事件描述
    - 将视觉描述、caption、ASR 片段融合为统一的语义摘要文本
    - 为下游 Agent 输出纯文本上下文包

### Module 5：Consistency Checker
- **功能**：评估视觉描述与 caption 叙述是否一致
- **输入**：`visual_description`, `local_caption`
- **输出**：`consistency_comment`
- **内部算法逻辑**：
    - 使用 LLM 判断两段描述是否表达相同事件、场景和动作
    - 若一致性低，则要求上游重新生成视觉描述，或在下游提示中标记“不确定窗口”

### Module 6：Memory Bank
- **功能**：维护长期记忆
- **输入**：当前窗口表示、得分、caption
- **输出**：`MemoryState`
- **内部算法逻辑**：
    - 存储已选窗口的文本摘要
    - 存储故事主线槽位文本
    - 存储冗余事件描述索引
  - 提供 read / update / topk_retrieve 接口

**实现约束：**
- Memory Bank 是纯工程状态管理模块；
- 记忆读写、压缩、淘汰必须是规则式或检索式；
- 不使用可训练 memory controller。

建议记忆拆成 4 类：
1. `story_memory`
2. `selected_memory`
3. `redundancy_memory`
4. `temporal_memory`

### Module 7：Planner Agent
- **功能**：动态任务规划与专家路由
- **输入**：`window_context_text`, `summary_goal_text`, `MemoryState`
- **输出**：`PlannerOutput`
- **内部算法逻辑**：
  - 读取当前窗口和记忆上下文
    - 使用 LLM 根据任务目标、历史记忆和当前窗口语义生成专家调用建议
  - 可附带 focus points 作为解释

**LLM-native 实现说明：**
- Planner Agent 不输出数值路由权重；
- 它输出文本化的路由计划，例如：
    - 优先关注主线推进；
    - 其次检查是否为重复片段；
    - 若场景突变明显，再调用事件高光专家重点审查。

### Module 8：Expert Agents
所有 Expert Agent 统一改为 **LLM reasoning module**。

每个 Agent 的接口统一为：  
`run(agent_input_text) -> agent_output_text`

#### 8.1 Mainline Agent

**Agent Goal**  
判断当前窗口是否推动视频主线、补充故事发展、引入新的关键叙事信息。

**Input（Text）**
- 当前窗口语义摘要
- 当前视频的全局故事目标
- 已记录的主线记忆摘要

**Output（Text）**
- 主线推进判断：`强 / 中 / 弱`
- 一句核心结论
- 简短理由

**LLM Prompt**
```text
你是 Mainline Agent，负责判断当前视频窗口是否推动整段视频的主线叙事。

输入信息：
1. 全局摘要目标：{summary_goal}
2. 当前窗口摘要：{window_summary}
3. 已有主线记忆：{story_memory}

请判断：当前窗口是否为主线带来新的推进，而不是重复已有情节。

输出必须使用以下格式：
Mainline Judgment: <强/中/弱>
Conclusion: <一句话结论>
Reason: <不超过两句话的理由>
```

**Reasoning Strategy**
- 先理解全局故事目标；
- 再判断当前窗口是否带来新的情节推进；
- 最后比较它与已有主线记忆是否重复。

#### 8.2 Event Agent

**Agent Goal**  
判断当前窗口是否包含值得进入摘要的关键事件、高光时刻或情绪峰值。

**Input（Text）**
- 当前窗口视觉描述
- 当前窗口 caption
- 可选 ASR 文本

**Output（Text）**
- 事件重要性：`高 / 中 / 低`
- 事件类型标签
- 判断理由

**LLM Prompt**
```text
你是 Event Agent，负责识别当前窗口是否包含关键事件、高光动作、高潮情绪或值得保留的瞬间。

输入：
1. 视觉描述：{visual_description}
2. 局部描述：{local_caption}
3. ASR（若有）：{asr_text}

请判断该窗口是否属于摘要中的高价值事件。

请按以下格式输出：
Event Importance: <高/中/低>
Event Type: <事件类型>
Reason: <简明理由>
```

**Reasoning Strategy**
- 从场景变化、动作强度、语义冲突和情绪表达中寻找高光信号；
- 若只是平稳过渡内容，则降低重要性判断。

#### 8.3 Novelty Agent

**Agent Goal**  
判断当前窗口是否与历史已选内容重复，或是否提供新的语义信息。

**Input（Text）**
- 当前窗口摘要
- 已选摘要记忆
- 最近若干窗口摘要

**Output（Text）**
- 新颖性判断：`高 / 中 / 低`
- 是否重复：`是 / 否 / 部分重复`
- 简短解释

**LLM Prompt**
```text
你是 Novelty Agent，负责判断当前窗口与已经保留的摘要内容相比，是否包含新的信息。

输入：
1. 当前窗口摘要：{window_summary}
2. 已选摘要记忆：{selected_memory}
3. 最近上下文：{recent_context}

请判断该窗口是否重复已有内容，还是提供了新的场景、动作、信息或叙事价值。

输出格式：
Novelty: <高/中/低>
Repetition: <是/否/部分重复>
Reason: <简短说明>
```

**Reasoning Strategy**
- 先对比当前窗口和已选记忆的主题与事件；
- 若只是同一事件的重复展示，则标记低新颖性；
- 若补充新的信息点，则标记中高新颖性。

#### 8.4 Temporal Agent

**Agent Goal**  
判断当前窗口是否有助于摘要的时序连续性、观看流畅性和叙事衔接。

**Input（Text）**
- 前一窗口摘要
- 当前窗口摘要
- 后一窗口候选摘要或未来局部上下文
- 当前摘要片段链路

**Output（Text）**
- 时序价值：`高 / 中 / 低`
- 衔接作用：`承接 / 过渡 / 跳跃 / 可省略`
- 简短说明

**LLM Prompt**
```text
你是 Temporal Agent，负责评估当前窗口对摘要叙事连续性的作用。

输入：
1. 前序摘要：{prev_summary}
2. 当前窗口摘要：{current_summary}
3. 后续候选摘要：{next_summary}
4. 当前已选摘要链：{summary_chain}

请判断当前窗口是否能帮助摘要更加连贯，还是属于可以省略的片段。

输出格式：
Temporal Value: <高/中/低>
Transition Role: <承接/过渡/跳跃/可省略>
Reason: <简短说明>
```

**Reasoning Strategy**
- 关注当前窗口是否连接前后关键事件；
- 如果删除该窗口会导致剧情跳跃，则提高时序价值；
- 若它只是冗长过渡，则降低重要性。

#### 8.5 Domain Agent

**Agent Goal**  
根据视频类型、主题偏好和摘要目标，判断当前窗口是否符合该领域的摘要保留策略。

**Input（Text）**
- 视频主题说明
- 领域类型或主题分布描述
- 当前窗口摘要

**Output（Text）**
- 领域匹配度：`高 / 中 / 低`
- 领域策略意见
- 简短说明

**LLM Prompt**
```text
你是 Domain Agent，负责根据视频类型判断当前窗口是否符合该领域的摘要偏好。

输入：
1. 视频主题：{video_theme}
2. 领域说明：{domain_hint}
3. 当前窗口摘要：{window_summary}

请结合该类型视频的常见摘要偏好，判断当前窗口是否值得保留。

输出格式：
Domain Match: <高/中/低>
Policy Suggestion: <一句策略意见>
Reason: <简短说明>
```

**Reasoning Strategy**
- 先识别视频类型；
- 再用对应领域的摘要偏好解释当前窗口价值；
- 输出领域化保留建议。

### Module 9：Counterfactual Marginal Contribution Critic
- **功能**：估计当前窗口对摘要的真实边际价值
- **输入**：`MemoryState`, `window_summary_text`, `summary_goal_text`
- **输出**：`counterfactual_comment`
- **内部算法逻辑**：
    - 让 LLM 以“保留 / 删除”两个反事实视角比较当前窗口的价值
    - 输出当前窗口是否不可替代、是否仅是重复补充、是否会影响主线完整性

**LLM-native 设计**

**Agent Goal**  
判断“如果删除当前窗口，摘要会失去什么”。

**Input（Text）**
- 当前摘要记忆
- 当前窗口摘要
- 全局摘要目标

**Output（Text）**
- 边际贡献：`高 / 中 / 低`
- 删除后损失描述
- 保留建议

**LLM Prompt**
```text
你是 Counterfactual Critic，负责评估当前窗口的不可替代性。

输入：
1. 当前摘要记忆：{memory_summary}
2. 当前窗口摘要：{window_summary}
3. 全局摘要目标：{summary_goal}

请分别思考：
A. 如果保留该窗口，摘要获得了什么？
B. 如果删除该窗口，摘要失去了什么？

输出格式：
Marginal Contribution: <高/中/低>
Loss If Removed: <一句话描述>
Recommendation: <保留/可省略/视预算决定>
```

**Reasoning Strategy**
- 用反事实方式衡量窗口是否不可替代；
- 优先关注主线损失、事件缺失和摘要理解断裂。

### Module 10：Score Aggregator
- **功能**：聚合专家分数和 CMCC 分数
- **输入**：专家文本意见、Planner 路由计划、CMCC 评论
- **输出**：`WindowScore`
- **内部算法逻辑**：  
    - 读取所有专家 Agent 的文本判断；
    - 按 Planner 指定的优先级综合意见；
    - 输出当前窗口的最终重要性结论与保留建议。

**LLM-native 设计**

**Agent Name**  
Aggregation Agent

**Agent Goal**  
综合多个专家意见，给出统一的窗口级重要性判断。

**Input（Text）**
- Planner 路由说明
- Mainline / Event / Novelty / Temporal / Domain / CMCC 的输出文本

**Output（Text）**
- 最终重要性：`必须保留 / 建议保留 / 可选 / 建议省略`
- 决策理由
- 冲突处理说明

**LLM Prompt**
```text
你是 Aggregation Agent，负责综合多个专家的文本判断，给出当前窗口的最终重要性结论。

输入：
1. Planner 路由计划：{planner_plan}
2. Mainline Agent 输出：{mainline_output}
3. Event Agent 输出：{event_output}
4. Novelty Agent 输出：{novelty_output}
5. Temporal Agent 输出：{temporal_output}
6. Domain Agent 输出：{domain_output}
7. Counterfactual Critic 输出：{critic_output}

请基于这些信息，输出最终窗口决策。

输出格式：
Final Importance: <必须保留/建议保留/可选/建议省略>
Reason: <两句话以内>
Conflict Handling: <如有专家冲突，说明如何裁决>
```

**Reasoning Strategy**
- 先遵循 Planner 的关注优先级；
- 若多个专家冲突，则优先保留主线、关键事件和不可替代内容；
- 统一输出最终决策文本。

### Module 11：Frame Score Fusion
- **功能**：窗口级到帧级映射
- **输入**：`List[WindowScore]`, `List[Window]`
- **输出**：`frame_scores`
- **内部算法逻辑**：
    - 将每个窗口的文本重要性结论映射为离散优先级标签
    - 对重叠窗口采用规则式冲突消解
    - 生成帧级或片段级的重要性区间说明

### Module 12：Budgeted Summary Selector
- **功能**：预算约束下选择摘要片段
- **输入**：`frame_scores`, `budget`
- **输出**：`selected_segments`
- **内部算法逻辑**：
    - 先整理候选片段的文本重要性标签与理由
    - 再由 LLM 在预算约束下选择最值得保留的片段组合
    - 同时兼顾主线完整性、事件覆盖和去冗余

**LLM-native 设计**

**Agent Name**  
Selection Agent

**Agent Goal**  
在预算限制下，选择最值得进入最终摘要的片段集合。

**Input（Text）**
- 候选片段列表
- 每个片段的重要性结论
- 预算说明
- 当前摘要目标

**Output（Text）**
- 入选片段清单
- 每个片段的入选原因
- 预算使用说明

**LLM Prompt**
```text
你是 Selection Agent，负责在预算约束下选择最终摘要片段。

输入：
1. 候选片段列表：{candidate_segments}
2. 每个片段的重要性说明：{segment_importance_reports}
3. 摘要预算：{budget_description}
4. 全局摘要目标：{summary_goal}

请在预算范围内，选择最能代表主线、关键事件和整体信息价值的片段组合。

输出格式：
Selected Segments: <片段ID列表>
Selection Reasons: <逐条简述原因>
Budget Note: <预算是否用满、为何取舍>
```

**Reasoning Strategy**
- 优先保留主线关键片段和不可替代事件；
- 再补充少量过渡片段保证可读性；
- 删除明显重复片段。

### Module 13：Explanation & Logging Module
- **功能**：记录 Agent 决策依据
- **输入**：Planner 输出、专家分数、记忆状态摘要
- **输出**：JSON 日志 / 可视化输入文件
- **内部算法逻辑**：
  - 保存每窗口 route weights
  - 保存 top memory matches
  - 保存最终选择原因

## 2.4 Agent 结构说明

## Agent 角色
1. **Planner Agent**：总调度者
2. **Mainline Agent**：主线推进判断
3. **Event Agent**：高光事件判断
4. **Novelty Agent**：去冗余
5. **Temporal Agent**：时序可观看性
6. **Domain Agent**：领域偏好
7. **CMCC Critic**：统一边际效用校准器

## Agent 工具
- 文本记忆检索
- 结构化提示模板
- JSON / 结构化文本输出约束
- 可选 LLM prompt 推理
- 上下文摘要与历史片段引用

## Agent 决策逻辑
- Planner 根据当前窗口文本、全局目标文本和历史记忆文本生成路由计划
- 各专家基于纯文本上下文独立推理
- CMCC 提供反事实文本评论
- Aggregation Agent 合成最终窗口决策
- Selection Agent 在预算约束下完成最终片段选择

## Agent 交互方式
- **串行主流程**
  1. Memory read
  2. Planner route
    3. Experts reason
  4. Critic calibrate
    5. Aggregation decide
    6. Memory update

- **不建议** 初期做多轮自由对话式 Agent 协作  
    工程上应先实现为**结构化函数调用式多 Agent**，更稳定、可测、可控。

# 5. 关键算法伪代码

## 5.1 滑动窗口构造

```python
def build_windows(total_frames, win_len, overlap, sample_rate):
    step = win_len - overlap
    windows = []
    start = 0
    win_id = 0

    while start < total_frames:
        end = min(start + win_len, total_frames)
        frame_indices = uniform_sample_indices(start, end, sample_rate)

        windows.append({
            "win_id": f"w_{win_id}",
            "start_frame": start,
            "end_frame": end,
            "sampled_frame_indices": frame_indices
        })

        if end == total_frames:
            break

        start += step
        win_id += 1

    return windows
```

## 5.2 多模态融合

### 数据结构
- `visual_description`: 当前窗口的视觉描述文本
- `local_caption`: 当前窗口的局部事件描述文本
- `asr_text`: 当前窗口的语音文本
- `semantic_summary`: 融合后的统一语义摘要文本

### LLM-native 说明
不再进行显式特征融合计算，而是将视觉描述、caption、ASR 组织为统一文本上下文，供下游 Agent 使用。

### 伪代码
```python
def build_window_context_text(visual_description, local_caption, asr_text=None):
    parts = [
        f"Visual Description: {visual_description}",
        f"Local Caption: {local_caption}",
    ]
    if asr_text:
        parts.append(f"ASR: {asr_text}")
    parts.append("Task: Summarize the current window in a concise, factual manner.")
    return "\n".join(parts)
```

```python
    selected_ctx = retrieve_relevant_texts(memory.selected_memory, current_summary, topk)
    story_ctx = retrieve_relevant_texts(memory.story_memory, current_summary, topk)
    temporal_ctx = memory.temporal_memory[-topk:]
    return {
        "selected_ctx": selected_ctx,
        "story_ctx": story_ctx,
        "temporal_ctx": temporal_ctx,
    }

def memory_update(memory, current_summary, final_decision, is_selected):
    memory.temporal_memory.append(current_summary)

    if is_selected:
        memory.selected_memory.append(current_summary)

    if final_decision in ["必须保留", "建议保留"]:
        memory.story_memory.append(current_summary)

    memory.redundancy_memory.append(current_summary)
    memory = trim_memory(memory)
    return memory
```

# 6. 工程实现建议

## 6.1 实现难度最高的模块

### 1. 全局理解模块
原因：
- Video LLM 成本高
- 粗分段 caption 质量波动大
- 主题归纳易受幻觉影响

### 2. Planner Agent
原因：
- 需要稳定地把“目标 + 当前窗口 + 记忆”转为合理路由
- 若直接用 LLM，推理成本和可控性较差

### 3. CMCC 反事实评论家
原因：
- 反事实 Prompt 需要稳定地产生一致判断
- 删除/保留视角可能受上下文组织方式影响

### 4. 多 Agent 协作的一致性
原因：
- 各专家文本判断口径可能不一致
- 容易出现某一专家长期主导

---

## 6.2 可以先用简化版本的模块

### 可简化 1：Global Understanding
先用：
- 分段 caption 拼接
- 简单 LLM 汇总  
代替复杂多阶段聚合。

### 可简化 2：Planner
先用固定权重、规则函数或冻结 LLM 路由。

### 可简化 3：Event Agent
先用：
- 局部视觉描述
- 事件关键词
- caption 中事件词  
做启发式估计。

### 可简化 4：CMCC
先用启发式效用函数，不做学习式 critic。

### 可简化 5：Segmenter
先用定长切分，不做镜头检测。

---

## 6.3 最小可运行版本（MVP）

建议 MVP 只保留 6 个核心部件：

1. **固定窗口切分**
2. **视觉内容文本化**
3. **简单文本描述**
4. **Memory Bank**
5. **3 个核心专家**
   - Mainline
   - Novelty
   - Event
6. **窗口到帧映射 + 贪心摘要选择**

### MVP 不做的内容
- 不做复杂 Planner
- 不做复杂 Domain Agent
- 不做学习式 CMCC
- 不做在线协议
- 不做多轮 LLM 推理
- 不做任何训练、微调、蒸馏或参数学习

### MVP 流程
```text
Video
-> Windows
-> Visual/Text Features
-> Memory Read
-> Mainline + Novelty + Event
-> Fixed-weight Score
-> Memory Update
-> Frame Fusion
-> Budgeted Selection
```

这样可在较短时间内得到一个真实可跑的 baseline。

## 6.6 实验协议建议

建议实现两种模式：

### Offline-Streaming
- 可先读取全视频做全局理解
- 再按窗口顺序处理
- 更适合论文主实验

### Online-Streaming
- 只允许访问当前及历史
- 全局目标动态更新
- 更适合真实流式部署
